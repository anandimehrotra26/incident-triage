# Data provenance

## What the data is

| file | rows | what |
|---|---|---|
| `incidents.csv` | 900 | Synthetic logistics incident reports in 9 categories (the base task). |
| `incidents_coldchain_ext.csv` | 120 | Synthetic reports for a 10th category, `cold_chain_excursion`, used only in the changed-requirement experiment. |
| `review/review_sheet_blank.csv` | 60 | Blind sample of `incidents.csv` (labels removed) for independent human review. **Review is pending - see below.** |
| `DATASET_STATS.md` | - | Auto-generated class counts, urgent counts, distinct-text and distinct-template counts. |

## Where it came from

**Entirely synthetic. There is no real, customer or confidential data in this repository.**

- Generated by `triage/data_gen.py` (`python -m triage.data_gen`), seed 42 (extension: seed 43). Re-running reproduces the files byte for byte.
- Author of the fragments: an AI assistant (Claude, Anthropic), working from a prompt by the project owner describing a logistics operator's incident triage problem. The fragments are generic, invented sentences ("forklift overturned and the operator is not responding"); site names, reference numbers and vehicle IDs are random or fictional.
- Each report = one hand-written core sentence (125 distinct core templates in the base file) + random slot values (IDs, quantities, sites) + optional opener, second clause, trailing request, and degradation (typos, abbreviations, lower-casing, truncation).

## Columns

| column | meaning | visible to models? |
|---|---|---|
| `id` | report id | no |
| `text` | the report | **yes (only input)** |
| `category` | the *recorded* category label (includes simulated clerk errors) | training target / evaluation truth |
| `urgent` | 1 if immediate (<30 min) action is needed (see `docs/LABELING_GUIDE.md`) | training target / evaluation truth |
| `category_true` | what the generator intended, before label noise | **never**; simulation-only diagnostic |
| `label_noise_injected` | 1 if `category` was deliberately flipped | **never**; simulation-only diagnostic |
| `hard` | generator flagged the report as hard (extra clause, over-escalation, heavy typos, or vague) | **never**; analysis only |
| `template_id` | which core sentence was used, e.g. `hazmat_spill|U|3` | only for the unseen-template split and grouped CV |

## Deliberate imperfections (so the evaluation is not trivial)

- **Class imbalance:** 5-22% per category; urgent rate 21% overall and very different per category (8% for cargo damage, 56% for hazmat).
- **Unreliable urgency language:** only ~45% of urgent reports start with an urgency opener ("URGENT:", "ASAP", "Emergency!"); the rest rely on content. ~7% of non-urgent reports are prefixed "URGENT:" or similar.
- **Distractors:** ~18% carry a clause about another category ("this will probably delay the delivery"); ~10% of routine reports outside the accident/hazmat categories add "no injuries", "no spill" or similar.
- **Vague reports:** `unclear_other` (9%) is intentionally unroutable ("can someone look at this please"); 20% of those use alarming wording and are labelled urgent.
- **Label noise:** 3% of recorded `category` values (20/900) are flipped to a plausible confusable category, simulating intake-clerk error. This puts a ceiling of roughly 97% on measured category accuracy.

## Known limitations (read before trusting any number)

1. **Template-derived text is far more regular than real incident reports.** Real reports are longer, messier, multilingual, and contain phrasing nobody planned for. Scores on this data are optimistic; the unseen-template split is a stress test, not a prediction.
2. **Only 125 core sentences (about 14 per category).** Models can memorise them. This is why the main evaluation reports a second, harsher split that hides entire templates.
3. **One author wrote both the data and the rules baseline.** Vocabulary leaks between them. A first draft of the rules baseline contained ~25 words copied from the templates; they were removed before reporting (see `docs/MODEL_SELECTION.md`), but residual leakage through shared domain vocabulary is unavoidable.
4. **Labels follow one author's rules** (`docs/LABELING_GUIDE.md`). A real operator would define urgency and category boundaries differently.
5. **Independent label review has not been done yet.** The brief asks for >=50 labels to be reviewed by someone independent of the labeller. The AI assistant that wrote the generator is not independent, so no review is claimed. The blind sheet, instructions and scoring script are provided (`data/review/`, `triage/review.py`); until a person completes the sheet this requirement is **open**.
